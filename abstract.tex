\begin{abstract}
Graphical applications require fast rasterization libraries
  to quickly and efficiently raster application user interfaces
  to pixels on the screen
  and to update those pixels as animations and user interactions occur.
The most common such library is Skia,
  used in all major browser engines,
  in the Android operating system,
  the Flutter mobile application framework,
  and many other applications.
While Skia does contain highly-efficient GPU kernels
  for drawing shapes, blending drawings, and applying effects,
  using it effectively also requires
  generating efficient sequences of Skia commands.
Yet doing is is difficult due to Skia's complex semantics
  and the need to deeply understand its execution model.
Even highly-optimized applications like Google Chrome
  consistently generate suboptimal Skia commands,
  leading to slower rasterization than necessary.

To address this issue,
  we introduce a new formal semantics of Skia,
  including its command language,
  a functional drawing and blending language,
  and an abstract model of shapes and colors.
To demonstrate the utility of this semantics,
  we use it to verify optimizations for
  common sub-optimal patterns commands generated by Google Chrome.
Using those patterns,
  we then develop a Skia optimizer,
  which can rewrite in-memory Skia programs in microseconds
  to speed up rasterization.
On a collection of \grmtlnumbench Skia programs
  gathered from the top 100 websites,
  this optimizer improves rasterization time on \grmtlnumspmatch,
  with speedups ranging from \grmtlspmatchmin to \grmtlspmatchmax,
  while compilation time is at most \grmtlmaxopttime,
  across a variety of websites, Skia backends, and hardware setups.
\end{abstract}
