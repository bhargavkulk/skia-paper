\begin{abstract}
Graphics applications display visual infromation on computer screens
  via a process called \emph{rasterization}.
Rasterization is powered by libraries like Skia, CoreGraphics, and Direct2D
  which consume series of instructions describing the visual information to be
  drawn, along with various effects and blends.
Rasterization must be smooth for end users, and thus these libraries are heavily
  optimized.
But clients of these libraries often generate inefficient sequences of
  intructions for these libraries.
Moreover, it is hard for clients to generate efficient programs
  because the udnerlying models of execution of these libraries are opaque and
  non-obvious.

To address this issue,
  we introduce \muskia,
  a formal semantics for the Skia 2D graphics library,
  mechanized in Lean to allow automated reasoning and verification of
  \muskia programs.
To demonstrate the utility of this semantics,
  we use it to verify optimizations for
  common sub-optimal patterns of instructions generated by Google Chrome,
  found by manually inspecting the Skia programs generated by the top 100
  websites by traffic.
Using those patterns,
  we then develop a Skia optimizer,
  which can rewrite in-memory Skia programs in microseconds
  to speed up rasterization.
On a collection of \grmtlnumbench Skia programs
  gathered from the top 100 websites,
  this optimizer yields a speedup \grmtlgeospeedup
  over Skia's modern GPU backend.
Furthermore, compilation time is at most \grmtlmaxopttime,
  across a variety of websites, Skia backends, and hardware setups.
The programs generated by the optimizer can also be translation validated
  against the semantics mechanized in Lean.
\end{abstract}
