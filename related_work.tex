\section{Related Work}
\label{sec:related}

\paragraph{Web Browser Optimizations}
There has been of lot of research into optimizing various parts of the modern
  web browser.
The JavaScript and Layout engines have garnered the most interest.
Prior work on optimziing JavaScript engines have focused on different parts of
  the modern JavaScript engines used in browsers.
\citet{membalancer} introduces a new heap-sizing formula for Chrome's V8
JavaScript engine, \citet{tracemonkey} introduces a new JIT compilation strategy
for Firefox's JavaScrip engine.
While lot of layout engine optimiziation has focused on improving the core
  layout algorithm that renders websites.
\citet{parlayout} introduces a parrellel layout algorithm, \citet{layoutsynth}
introduces a synthesis algorithm for web browser layout engine algorithms, and
\citet{spineless} algorithmically improves on the core invalidation strategy
used in modern web browsers.
The work on layout engines is closest to the work introduced in this
  paper, but most layout engine work has focused on frame-to-frame re-renderering
  while we have focused on optimizing individual frames of rendering.

\paragraph{2D graphics}

The scheme of blending colors, which we describe in the abstract model in
  \Cref{sec:semantics}, was introduced by \citet{blendmodes}.
Also of note is \citet{pipeline}, which introduces a rudimentary rendering
  pipeline seperating the concerns between what is being drawn (objects and
  their spacial positions) and how it is being drawn (rendering).
In the vast modern literature of 2D graphics rendering and processing, the Halide
language stands out.
Halide, introduced in \cite{halide}, is a language helps in describing both the
  computation and scheduling of high performance 2D image processing kernels.
Later work, \citep{halide-auto, halide-tree} have focused on automatically
  generating performant computation schedules for Halide programs.
Of note to readers of this paper is work by \citet{halide-verif} on
  automatically verifying optimizing rewrites used in the Halide compiler.
Although Halide and the work in this paper both focus on trying to improve image
  rendering, Halide focuses on the underlying computation done while rendering,
  while our work focuses on the higher level ordering of drawing instructions
  prior to rendering.

\paragraph{Scene Graphs}

Skia's command API can be thought of as a 2D version of a scene graph. A scene
graph is a heirarchical data structure which describes the logical and spatial
arrangement of objects in (usually 3D) \emph{scene}.


\paragraph{Semantics for unusual domains}

The semantics introduced in this paper are specifically to reason about the
  equality of images, and programs that produce images.
There exists prior working on formalizing semantics for weirder, non-traditional
  prgramming languages.
Closest in relation to the work in this paper is work by \citet{cassius} on
  formalizing a significant portion of the CSS specification, and
  \citet{vizassert} which formalizes a large fragement of the browser rendering
  algorithm to verify assertions about web page layout.
A visual format that has also been a focus for formalization are for programs that
  describe physical 3D models, like CAD and G-code.
\citet{reincarnate} introduces denotational semantics for CAD programs into meshes, similiar
  to that of \Layer terms to \Image{}s in our work.
\citet{gcode} on the other hand introduces a semantics for the lower level
  G-code instructions used by 3D printing machines.
There is also a series of papers on both the higher and lower level semantics of
  knitting machines (\citet*{knitsem, knitequiv, ufo}).
