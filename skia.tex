\section{Skia}

In this section,
  we introduce the basics of the Skia's drawing API.
The next example demonstrates the API by drawing a rectangle.
All drawing happens into a canvas.\footnote{A canvas in Skia is represented by
  an instance of a \texttt{SkCanvas}~\cite{skcanvas} object, which owns all the drawing state.}

\begin{figure}[H]
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Draw(Rect1, DEFAULT_PAINT)
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing1.pdf}}
\end{minipage}
\end{figure}

The example is shown in three parts:
  the canvas before the draw call,
  the draw command itself,
  and the canvas after execution.
The drawing before the \texttt{Draw} command
  is an empty pixel buffer.
The drawing after the \texttt{Draw} command
  is a pixel buffer with a black square.
\texttt{Draw} needs 2 arguments:
  the geometry to be drawn,
  and a \texttt{Paint}.\footnote{In the actual \texttt{SkCanvas} API,
    \texttt{Draw} is not overloaded over all geometries, but instead there exist
    specific \texttt{Draw*} methods for the geometries Skia supports.}

A \texttt{Paint}~\cite{skpaint} controls how a geometry is drawn.
For example,
  you can specify a fill color in a \texttt{Paint}.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Draw(Rect1,
      Paint(Color(Red), ...))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing2.pdf}}
\end{minipage}
\end{center}

A fill does not need to be a constant fill of the same pixel.
More interesting fills can be implemented with gradients:

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Draw(Rect1,
      Paint(LinearGradient(...), ...))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing3.pdf}}
\end{minipage}
\end{center}

You can also specify a blend mode for a \texttt{Paint},
  which governs how the geometry is drawn on to existing pixels of the canvas.
For example,
  the blend mode \texttt{SrcOver} encodes the intuitive idea
  of drawing one shape on top of the other.
In the following example,
  we blend a blue square over the red square we previously drew,
  using \texttt{SrcOver} blending.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Draw(Rect2,
      Paint(Color(Blue), ..., SrcOver))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing6.pdf}}
\end{minipage}
\end{center}

Another blend mode common blend mode is \texttt{DstIn}.
  \texttt{DstIn}.
If a geometry is blended with \texttt{DstIn},
  instead of being drawn on top the canvas,
  like in \texttt{SrcOver},
  it is instead used as mask over the canvas.
Consider the previous example,
  drawn using \texttt{DstIn} instead of \texttt{SrcOver}.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Draw(Rect2,
      Paint(Color(Blue), ..., DstIn))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing8.pdf}}
\end{minipage}
\end{center}

While \texttt{DstIn} can be used to mask drawings in this way,
  Skia also provides a dedicated clipping command for expressing this
  operation more directly.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Clip(Rect2, Intersect);
Draw(Rect1,
      Paint(Color(Red), ..., SrcOver))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing9.pdf}}
\end{minipage}
\end{center}

Now instead masking being a consequence of blending,
  we mask by constraining the draw geometry
  by intersecting it with a clip.
The current global clip state is maintained by the canvas,
  and \texttt{Clip} commands modify the globla clip state.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Clip(Rect(64, 64, 192, 192), Intersect);
Draw(Rect(0, 0, 128, 128),
      Paint(Color((1, 1, 0, 0)), ..., SrcOver));
Draw(Rect(128, 128, 256, 256),
      Paint(Color((1, 0, 0, 1)), ..., SrcOver))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing10.pdf}}
\end{minipage}
\end{center}

Skia does not maintain just one clip state,
  but rather a stack of them.
The current canvas clip state is the clip on the top of the clip stack.
\texttt{Clip} commands always modify the top of the clip stack,
  and can not touch the states below it.
Skia provides the \texttt{Save()} and \texttt{Restore()} commands
  to manipulate the clip state.
\texttt{Save()} duplicates the top of the clip stack on to the stack,
  and a matching \texttt{Restore()} pops the top of the stack.
\texttt{Save()} and \texttt{Restore()} allow us to restrict
  the effects of \texttt{Clip} commands to a group of commands.

\begin{center}
\begin{minipage}[c]{0.45\textwidth}
\begin{BVerbatim}
Save();
  Clip(Rect(64, 64, 192, 192), Intersect);
  Draw(Rect(0, 0, 128, 128),
        Paint(Color((1, 1, 0, 0)), ..., SrcOver));
Restore();
Draw(Rect(128, 128, 256, 256),
      Paint(Color((1, 0, 0, 1)), ..., SrcOver))
\end{BVerbatim}
\end{minipage}\hfill
\begin{minipage}[c]{0.45\textwidth}
\centering
\frame{\includegraphics[scale=0.3]{drawing11.pdf}}
\end{minipage}
\end{center}
