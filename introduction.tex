\section{Introduction}
\label{sec:intro}

Browser engines are an increasingly prominent way
  that users interact with applications---%
  not only web applications like Office~365 or GMail
  but also desktop applications like Slack, Discord, and VS~Code.
Browser applications are graphical,
  and increasingly support complex graphical effects
  such as shadows, gradients, transparency, and animations.
These features require high-performance
  to draw and redraw the application 60 or even 120 times per second
  to produce smooth animations and keep up with user interactions.
A critical part of high performance is fast rasterization,
  the task of actually determining
  the color of each pixel drawn by the application,
  generally from a high-level description of shapes to be drawn
  and effects to be applied.
A browser must typically do all this for millions of pixels
  in the span of hundreds of microseconds.

This requires highly-optimized rasterization libraries.
The most prominent of these libraries is Skia.
Skia is used by all prominent browser engines---%
  it is the only rasterization library
  for the Google Chrome, Mozilla Firefox, and Ladybird browsers,
  and the Linux rasterization library
  for the Webkit engine behind Apple Safari.
Skia is additionally used in the Android operating system,
  is one of two rasterization options in Flutter,
  a popular mobile application framework,
  and is also a popular backend for various libraries
  for rastering PDFs, images, and icons.
Skia allows clients to describe shapes to be drawn,
  define how different shpaes are blended together,
  and apply effects.
Skia then converts this description
  into an efficient sequence of GPU shader calls
  using GPU backends tuned for various native APIs
  like Metal, Vulkan, and OpenGL.
Skia is popular because it has wide support across many GPUs,
  and it highly efficient.

However, to achieve max performance,
  clients must use Skia in the right way.
Clients' choice of API methods can cause Skia
  to allocate additional pixel buffers,
  perform additional blend operations,
  or switch from special-case to slower, general-purpose masking routines.
Even sophisticated clients like Google Chrome
  generate subpar sequences of Skia commands
  due to the complexity of the Skia API
  and the clients' own internal complexity.
Moreover, less sophisticated clients
  have little hope of always performing
  the most optimal sequence of API calls
  and are therefore stuck with suboptimal rasterization performance.
Ideally, these concerns would be handled internally,
  by an optimization pass within the Skia library,
  but to date no such optimization pass exists.
Moreover, developing one is hindered by
  Skia's complex semantics.

To address this, we develop \muskia, a formalization of the Skia API.
\muskia captures key API features
  like canvas state, the layer stack, clipping, and blending.
\muskia is structured as a command language
  with an operational semantics defined in terms of a functional core;
  the functional core itself denotes to an abstract model of 2D graphics;
  and the abstract model permits multiple instantiations
  to allow reasoning module anti-aliasing and discretization error.
The semantics, including various real-world extensions,
  is mechanized in Lean
  and used to prove various \N rewrite rules
  that serve to optimize common sub-optimal patterns of Skia commands
  generated by Google Chrome on real-world websites.

We then develop an optimizer for Skia using these rewrite rules.
We demonstrate the optimizer on a collection
  of Skia programs generated by Google Chrome
  on the Alexa Top 100 websites.
Considering the \N Skia programs that use complex blending effects,
  our optimizer is able to improve rasterization time on \N,
  with speedups ranging from \N to \N.
The optimizer is also highly efficient
  and provides speedups even inclusive of optimization time.
The optimizer is correct,
  with only relatively small pixel differences caused by anti-aliasing.
Moreover,
  the optimizer produces optimization traces
  that can be loaded into Lean
  for translation validation against our semantics.
Finally, the optimizer is effective
  across a variety of Skia backends and GPUs,
  and also speeds up rasterization
  on a second, ``out of sample'' set of Skia programs
  that the authors did not use when developing the optimizer.

\medskip
The contributions to this paper are:
\begin{enumerate}
\item A new formalization of the Skia API (\Cref{sec:semantics})
\item A collection of rewrites proven valid using this formalization (\Cref{sec:rules})
\item A optimizer that speeds up real world Skia rasterization (\Cref{sec:compiler}).
\end{enumerate}
