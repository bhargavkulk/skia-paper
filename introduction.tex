\section{Introduction}
\label{sec:intro}

Every pixel you see on a computer screen
  was produced by a process called \emph{rasterization}.
In this process, programs like desktop, mobile, and web applications
  generate a series of instructions to a \emph{rasterization library}
  describing operations like drawing shapes,
  rendering text, filling regions with color or gradients,
  and blending overlapping visual elements.
The rasterization library, which might be Skia, CoreGraphics, or Direct2D,
  then executes the operations,
  ultimately determining the color of every pixel,
  and then presents the resulting image on the screen.
Skia particullarly enjoys widesprea use,
  being the rasterization library of choice for
  the Google Chrome, Firefox, and Ladybird browsers,
  the Android operating system, the Flutter mobile application framework,
  as well as for native applications like Sublime Text.

Rasterization must be done at interactive rates,
  ideally 60 to 120 frames per second,
  to ensure a smooth experience for users.
To do so, libraries ensure that each drawing command
  is executed as efficiently as possible.

Skia, for example,
  is as widely uses as it is because it targets
  a wide variety of CPU- and GPU-based backends
  using both legacy and modern graphics APIs like OpenGL, Vulkan, and Metal.
Each backend uses highly-optimized shaders
  to execute drawing commands as quickly as possible.
Hence there is not much performance to squeeze out of drawing the individual
  commands themselves,
  but what can be optimized is the program that Skia consumes,
  which can have an enormouse impact on performance.
Hence, clients must issue
  efficient command sequences to get good rasterization performance.
But doing so is difficult for even sophisticated clients.
Even Google Chrome, which is developed closely alongside Skia at Google,
  suffers from generating suboptimial Skia command sequences for some of the
  most visited websites in the world.

The reason is simple:
  rasterization libraries have opaque and non-obvious execution models
  which clients struggle to reason about.
The ideal solution would be a clear formal semantics.

We introduce \muskia,
  a formal semantics for the Skia 2D rasterization library.
\muskia captures key features of the Skia API
  like canvas state, the layer stack, clipping, and blending.
Our formalization is built in three strata---%
  a command language, a functional core, and an abstract model---%
  that seperate concerns, simplify reasoning, and allow for extensibility.
The semantics is mechanized in Lean
  which enables automated reasoning and verification of Skia programs.

To show the utility of \muskia semantics,
  we use the semantics to derive correct and verified rewrites for Skia.
We inspected Skia programs generated by Google Chrome for the top 100 websites
  in the world by traffic, and identify four suboptimal patterns.
We then come up with more performant alternatives to these platforms,
  and then formally prove the equality between the suboptimal patterns and their
  alternatives using \muskia{}'s semantics as  rewrite rules.
Finally, we build an optimizer that applies these rewrite rules
  to speed up rasterization.
We evaluate our optimizer on a collection
  of \grmtlnumbench Chrome-generated Skia programs
  from the top 100 websites.
The optimizer is able to improve rasterization time on \grmtlnumspmatch,
  with speedups ranging from \grmtlspmatchmin to \grmtlspmatchmax.
The optimizer is also highly efficient,
  with the largest Skia program taking just \grmtlmaxopttime to optimize,
  and introduces only minimal, anti-aliasing-driven output changes.
We also verify that rasterization speedups persist
  across Skia back-ends, different hardware platforms,
  and even on a hold-out set of additional websites.

\noindent
In short, the contributions in this paper are:
\begin{enumerate}
\item A new formalization of the Skia API (\Cref{sec:semantics})
\item A collection of rewrites proven valid using this formalization (\Cref{sec:rewrites})
\item A efficient and correct Skia optimizer that applies these rewrites (\Cref{sec:compiler}).
\end{enumerate}
