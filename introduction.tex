\section{Introduction}
\label{sec:intro}

Vast majority of people interact with applications via a wwb browsers.
% electron aps etc
Increasing trend of animation, fancy visuals, complex design has made web
  interface more visually complex.
This makes performance of web browsers prescient.
One crtical aspefct of web broser pefromance is rasterization,
  process of computing the color of each pixel on the screen,
  given the high lvl descritp of the shapes ot be drawn.
Fro this reason, web browsers use high perfomance rastdr librarys.

The most prominent of these libraries is Skia,
  which is used by Chrome on all platforms,
  but also used by Firefox and Safari on some platforms.
Skia is also used inside Android, Flutter and so on.
Skia's API allows clients to describe shapes to be drawn,
  define how different shpaes are blended together,
  and apply effects.
Skia converts this into a an efficient sequence of GPYU shader calls,
  using its GPU backends. % Ganesh Graphite
Skia is popular because it has wide support across many GPUs,
  and it highly efficient.

However,
  to aciheve max perf,
  clients must invoke the lirbray in the rigth way.
Specifically,
  clients have to be mindful of how many allocations they are going to force
  Skia to do,
  how and what order will Skia perform blends,
  and how to use general purpose vs optimized special case operations.
Even sophostaced clients like Chrome,
  geenrate subpar sequences of Skia commands
  due to the their own complicated internal architecture,
  and the complexity of the SKia API itself.

To addres this we develop a formal definition of the Skia API.
Our formalization,
  \muskia,
  captures key API features like, canvas state, layer stack, blending , and
  clipping.
The formalization contains an operation semantics for the command language,
  a denotational semantics for a functional core,
  an abstract model of 2D graphics,
  all mechanized in Lean.
The formalzation is sufficnet to prove correct
  valuable improvemnets to the Skia programs generated by Chrome
  on real world websites.
We additional develop an optimizer
  for the Skia based on our semantics and the rewrite we proved.
The optimizer operates in memory on Skia images before they are rasterized and
  applies the rewrite we have proven correct.
Moreover,
  the compiler can produce optimization traces which can be translation
  validated in Lean using our semantics.

We demonstrate that the optimizer is both correct and effective
  on a collection of SKia programs drawn on the ``Alexa top 100'' webpages.
On these wbepages, our optimizer is able to improve render time on x/100
webpages by applying \foo rewrite rules.
The runtime improvemnt varies from \foo to \foo.
Moreover,
  the optimizations are effective on a wide array of websites
  and also across various Skia backends and GPUs.
Thje optimizer also runs quickly enough for optimization to be peformed on evry
  frame.

The contributions to this paper are:
\begin{enumerate}
\item A new formalization of the Skia API.
\item A collection of rewrites proven in this formalization
\item A optimizer that applies these rewrite to real world Skia programs and
  achive signficant speedsup, while being correct.
\end{enumerate}
