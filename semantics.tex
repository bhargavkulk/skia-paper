The goal of this section is to develop a semantics for Skia
  through which we can show that two different Skia programs
  render to the same image.
To encode this, we will use the relation $=_{\textit{Image}}$,
  and we will define this relation in this section.

Our semantics of Skia is built around
  a simple abstract model of images and shapes,
  shown in \Cref{fig:model}.
An image is a mapping from \textsf{Point} to \textsf{Pixel},
  while a shape is a collection of \textsf{Points}.
We also describe in this abstract model the operations of a \texttt{Paint}.
A \textsf{Blend} is a binary operator over \textsf{Pixel}.
We also introduce a new field for \texttt{Paints} not seen in \Cref{sec:skia}
  in Skia called \textsf{Filters},
  which are basically transforms over \textsf{Pixel}.

Under these semantics,
  a Skia program is rendered to an \textsf{Image}.
Rendering occurs by taking \textsf{Shapes},
  filling them with primitive \textsf{Images},
  and then blending the results with a \textsf{Blend} together in various orders
  to yield more complicated \textsf{Images}.

Our abstract model is abstracted over \textsf{Point} and \textsf{Pixel}.
Concretely for Skia,
  \textsf{Point} is $\mathbb{R}^2$ and \textsf{Pixel} is $[0,1]^4$.

\subsection{Skia as Layers}

Skia does not permit
  arbitrary drawing and blending operations;
  instead, these always happen in a prescribed order.
We thus introduce the language of \textsf{Layers},
  shown in \Cref{fig:layer},
  which defines the core \texttt{Draw} and \texttt{BlendLayer} operations
  in Skia.
We focus on these two operations specifically
  because they are the core target of the optimizing compiler
  described in \Cref{sec:optimize}.
The \textsf{Layer} constructors can be defined in terms of the abstract model,
  as shown in \Cref{fig:denote}.

\begin{figure}
  \begin{align*}
    \denote{\texttt{Empty()}}(\textsf{pt})
    &= \mathsf{Transparent}\\[2pt]
    \denote{\texttt{Draw(l, s, p, c)}}(\mathsf{pt})
    &= \mathtt{blend_p}\left(\denote{\mathtt{l}(\mathsf{pt})},\;
       \begin{cases}
         \mathtt{fill_p}(\mathsf{pt}) & \mathsf{pt} \in \mathtt{s} \cap \mathtt{c} \\
         \mathsf{Transparent} & \textsf{otherwise}
       \end{cases}
       \right)\\[2pt]
    \denote{\texttt{BlendLayer(l\textsubscript{bot}, l\textsubscript{top},
    p)}}(\mathsf{pt})
    &= \mathtt{blend_p}\left(\denote{\mathtt{l_{bot}}}(\mathsf{pt}),\;
        \denote{\mathtt{l_{bot}}}(\mathsf{pt})
      \right)
  \end{align*}
  \label{fig:denote}
\end{figure}

\subsection{\muskia}

We now define \muskia which is our representation of the Skia API.

\begin{figure}
  \begin{tabular}{S M c T}
    Command & c & ::= & Draw($g$, $p$) \\
            &   & | & DrawText(string, $p$) \\
            &   & | & Clip($cl$, Intersect | Difference) \\
            &   & | & Save(); $c$; Restore() \\
            &   & | & SaveLayer($p$); $c$; Restore() \\
            &   & | & $c$; $c$ \\[1pt]
    Geometry & g,\;cl & ::= & Rect($\ldots$) | RRect($\ldots$) | Path($\ldots$) \\[2pt]
    Paint & p & ::= & Paint($f$, $st$, $c_f$, $b$) \\[2pt]
    Fill & f & ::= & Color(Pixel) | LinearGradient($\ldots$) | $\ldots$ \\[2pt]
    Filter & f & ::= & Id | Luma | $\ldots$ \\[2pt]
    BlendMode & b & ::= & SrcOver | DstIn | Src | $\ldots$\\
  \end{tabular}
  \label{fig:muskia}
\end{figure}

\noindent \muskia simplifies certain aspects of the actual Skia API:
The Skia API has separate \texttt{Draw} and \texttt{Clip} commands for each
  \textsf{Geometry},
  and not the overloaded function we present in the grammar.
The Skia API does not have structured constructs for \texttt{Save} and \texttt{SaveLayer}.

More crucially, we have omitted certain effects and commands from \muskia that
  are in Skia.
The \texttt{Style} tells Skia whether to fill or stroke the shape.
It can be considered as a function over \texttt{Geometry},
  basically modifying it.
Similarly,
  \texttt{MaskFilters} allow us to implement Gaussian blurs.
This could also be understood as functions over \texttt{Geometry},
  and omitting them does not affect our semantics at all.

Skia also provides facilities to transform, rotate, and perform other affine
  transformations.
It is well known that these transformations can be done using
  matrix multiplications.
So Skia maintains a transform state along with the layer and clip state.
The \texttt{Concat44} command multiplies a 4x4 matrix with the transform state,
  and affect the drawing of all commands after.
The transform state as a whole can be removed by multiplying
  the transform state of a command into the geometry
  and the clip, which is what we do.

Finally,
  we also omit image filters from our discussion of semantics.
Image filters are the final way to transform a layer prior to blending.
When a paint has an image filter,
  all drawing happens in a seperate pixel buffer,
  and the effect defined by the filter is applied to the entire buffer
  before its blended.
Image filters seem similiar to color and mask filters,
  but they allow more complicated effects,
  as they can act on groups of pixels instead of single pixels.

\subsection{Operational Semantics for Skia}

We now define an operational semantics for the Skia API.
These semantics will allows us to convert terms in \muskia
  to terms in \textsf{Layer}.
We first define a step relation $\longmapsto$:

\begin{align*}
\longmapsto&:\textsf{Command} \times \Sigma \to \Sigma
\end{align*}

\noindent$\Sigma$ is the canvas state:

\begin{align*}
\Sigma&:\textsf{List[Layer]} \times \textsf{List[Geometry]}
\end{align*}

\noindent
The canvas state has a reference to another canvas state,
  emulating a stack of layers and clips.
The following rules, define $\longmapsto$ over each command on \textsf{Command}.

\begin{mathpar}
  \inferrule
  { }
  {
    \langle
    \texttt{Draw(g, p)},
    \langle l :: L, c :: C \rangle
    \rangle
    \;\longmapsto\;
    \langle \texttt{Draw(l, g, p, c)} :: L, c :: C \rangle
  } \and
  \inferrule
  { }
  {
    \langle
    \texttt{Clip(c', Intersect)},
    \langle L, c :: C\rangle
    \rangle
    \;\longmapsto\;
    \langle L, c \cap c' :: C \rangle
  } \and
  \inferrule
  { }
  {
    \langle
    \texttt{Clip(c', Difference)},
    \langle L, c :: C \rangle
    \rangle
    \;\longmapsto\;
    \langle L, c / c' :: C \rangle
  } \and
  \inferrule
  {
    \langle
    \texttt{cmd},
    \langle L, c :: c :: C \rangle
    \rangle
    \;\longmapsto\;
    \langle L', c' :: c :: C \rangle
  }
  {
    \langle
    \texttt{Save(); cmd; Restore()},
    \langle L, c :: C\rangle
    \rangle
    \;\longmapsto\;
    \langle L', c :: C \rangle
  } \and
  \inferrule
  {
    \langle
    \texttt{cmd},
    \langle \texttt{Empty()} :: l :: L, c :: c :: C \rangle \rangle
    \;\longmapsto\;
    \langle l' :: l :: L, c' :: c :: C \rangle
  }
  {
    \langle
    \texttt{SaveLayer(p); cmd; Restore()},
    \langle l :: L, c :: C\rangle
    \rangle
    \;\longmapsto\;
    \langle \texttt{BlendLayer(l, l', p)} :: L, c :: C \rangle
  } \and
  \inferrule
  {
    \langle
    \texttt{cmd},
    \langle l :: L, c :: C \rangle \rangle
    \;\longmapsto\;
    \langle l' :: L, c' :: C \rangle \\
    \langle
    \texttt{cmd'},
    \langle l' :: L, c' :: C \rangle \rangle
    \;\longmapsto\;
    \langle l'' :: L, c'' :: C \rangle
  }
  {
    \langle
    \texttt{cmd; cmd'},
    \langle l :: L, c :: C \rangle
    \rangle
    \;\longmapsto\;
    \langle l^{\prime} :: L, c'' :: C \rangle
  }
\end{mathpar}

\noindent
$\longmapsto^*$ is the reflexive transitive closure of $\longmapsto$.
It can be proven that given the initial state $\langle [\texttt{Empty()}],
  [\mathcal{U}] \rangle$, $\longmapsto^*$ will never get stuck i.e.


\begin{equation*}
\forall\,\texttt{cmd}\,\exists\,l,\, c\;\text{s.t.}\;\langle \texttt{cmd}, \langle
[\texttt{Empty()}], [\mathcal{U}] \rangle \rangle \longmapsto^* \langle [l], [c] \rangle
\end{equation*}

\noindent
Given this fact,
  we can write down an evaluation function for terms in \muskia to
  \textsf{Image}.

\begin{gather*}
\textsf{eval} : \textsf{Command} \to \textsf{Image} \\
\textsf{eval}(c) = \llbracket l \rrbracket \;\textsf{where}\;\langle c, \langle [\texttt{Empty()}], [\mathcal{U}]
\rangle \rangle \longmapsto^* \langle [l], [C] \rangle
\end{gather*}

\noindent
We now have all the pieces to define \eqimg.

\begin{gather*}
\eqimg : \textsf{Command} \to \textsf{Command} \to \textsf{Command} \\
l \eqimg l' := \textit{eval}(l) = \textit{eval}(l')
\end{gather*}
